# Qadir — цифровая система управления пищевыми отходами АТУ

Хакатон ATU «Smart Food Industries», Трек 1. Команда **Qadir Team**.

«Нанның қадірі» — уважение к хлебу. Qadir заменяет бумажные таблицы учёта пищевых отходов АО «АТУ» и показывает не только «сколько выбросили», но и «сколько потеряли и что с этим делать».

Полный цикл: **форма со смартфона → проверка → единый реестр → аналитика → отчёт**.

**Рабочая версия:** https://qadir-atu.vercel.app · гость жюри: https://qadir-atu.vercel.app/login?guest=1 · открытая страница «Спасённые порции»: https://qadir-atu.vercel.app/rescue

## Что умеет

| Направление ТЗ | Реализация |
|---|---|
| Digital Forms | Форма каждой организации с её перечнем отходов по образцам АТУ, добавление нового вида прямо в форме, автоподстановка даты и ответственного, единица кг/л от вида отхода, итоги за день и месяц, проверки значений и предупреждение о дубле |
| Mobile Input | Экран от 360 px, выбор плитками, числовая клавиатура, автосохранение черновика, фото к записи, QR-код организации |
| Submission Workflow | Отчёт за месяц отправляется одним действием; статусы: черновик → отправлено → на проверке → принято / возвращено; возврат только с комментарием; принятый отчёт закрыт; история изменений |
| Organizations & Roles | 4 роли, реестр организаций, подключение новой организации без изменения кода |
| Consolidation & Reporting | Единый реестр принятых данных с фильтрами; свод за месяц / квартал / год; выгрузка в Excel по структуре бланков АТУ; контроль несдавших |
| Analytics | 5 графиков, сравнение периодов, доля пригодных к переработке, отклонения, CO₂-эквивалент |

Сверх обязательного:

- **Правильная метрика.** Отходы делятся на предотвратимые и неизбежные; считаются граммы на порцию, потери в тенге, CO₂-эквивалент.
- **Индекс достоверности отчёта.** Автопроверка ищет признаки заполнения «задним числом» и «на глаз»: записи пачкой, круглые и повторяющиеся значения, пропущенные дни, выбросы. Проверяющий видит оценку 0–100, причины и черновик комментария.
- **«Спасённые порции».** Столовая выставляет остатки дня со скидкой, студенты видят их на открытой странице `/rescue`.
- **Живое обновление.** Запись с телефона и решение проверяющего сразу видны на других экранах.
- **API электронных весов** с симулятором `/scale-sim` — стык с Треком 2.
- **Отчёт ЦУР 12.3** для ESG-отчётности, печать в PDF.
- **Сценарий «что если»:** перевод отходов с захоронения на переработку.
- Интерфейс на **русском и казахском**.
- **Telegram-бот** для быстрого ввода — отдельный модуль в папке `bot/`, ТЗ в [docs/telegram-bot-tz.md](docs/telegram-bot-tz.md).

## Запуск

Нужны Node.js 18+ и бесплатный проект [Supabase](https://supabase.com).

1. В Supabase откройте **SQL Editor**, вставьте и выполните `supabase/001_schema.sql`, затем `supabase/002_seed.sql`.
2. Скопируйте `.env.example` в `.env.local` и подставьте **Project URL** и **anon public key** (Supabase → Project Settings → API).
3. Установите зависимости и запустите:

```bash
npm install
```

```bash
npm run dev
```

Приложение откроется на `http://localhost:5173`. Команда `npm run dev` также показывает адрес в локальной сети — его можно открыть с телефона.

Сборка для хостинга: `npm run build` (папка `dist`). Для Vercel достаточно импортировать репозиторий и задать две переменные из `.env.example`.

## Сквозной сценарий (раздел 9 ТЗ)

1. Телефон: вход `iskander@qadir.kz` → форма столовой.
2. Внести 2–3 взвешивания — итоги за день и месяц пересчитываются сразу.
3. «+ новый вид» — добавить вид отхода, которого нет в образце.
4. «Отправить отчёт за месяц на проверку» — статус «Отправлено».
5. Ноутбук: вход `reviewer@qadir.kz` → «Проверка» → отчёт → «Вернуть на доработку» с комментарием.
6. Телефон: виден статус «Возвращено» и комментарий → исправить → отправить повторно → проверяющий принимает.
7. «Реестр»: данные появились, фильтры по организации, периоду и виду отходов.
8. «Аналитика»: графики обновились.
9. «Свод» → квартал → «Скачать Excel».
10. «Свод» → «Контроль сдачи отчётов»: кто не сдал.

## Безопасность

- Вход по e-mail и паролю (Supabase Auth); пароли хранятся только как bcrypt-хэш.
- Права проверяются **на сервере**: на всех таблицах включён Row Level Security. Ответственное лицо читает и меняет только свою организацию.
- Статус отчёта меняют только серверные функции `submit_report`, `start_review`, `decide_report` с проверкой роли; возврат без комментария отклоняет база.
- Записи отправленного и принятого отчёта нельзя изменить — запрет в политике базы, а не в интерфейсе.
- В браузер попадает только публичный anon-ключ. Сервисный ключ в приложении не используется; `.env.local` исключён из репозитория.
- Персональные данные — только служебные: ФИО и e-mail.
- Весы передают данные только по токену организации.
- Гостевая учётная запись жюри ограничена «Демо-точкой жюри», её данные не попадают в реестр и своды.

## Архитектура

```
Смартфон / ноутбук (React + Vite + Tailwind, статика на Vercel)
        │  HTTPS, anon-ключ + JWT пользователя
        ▼
Supabase
  ├─ Auth            вход, bcrypt-хэши паролей
  ├─ Postgres + RLS  таблицы, политики доступа по ролям
  ├─ SQL-функции     workflow отчёта, приём показаний весов
  └─ Realtime        живое обновление экранов
```

ER-диаграмма — в [docs/er.md](docs/er.md). Схема базы — `supabase/001_schema.sql`.

## Допущения и источники

- **CO₂-эквивалент:** 2,5 кг CO₂-экв. на 1 кг пищевых отходов — среднее по данным FAO, *Food Wastage Footprint: Impacts on Natural Resources* (2013): 3,3 Гт CO₂-экв. на 1,3 Гт пищевых потерь. Упаковка в расчёт не входит. Коэффициент редактируется в справочнике.
- **Потери в тенге** — оценочные цены-допущения команды по видам отходов, редактируются в справочнике. Неизбежные отходы (очистки, кости) в потери не входят.
- **Демо-данные сгенерированы**, это не реальные замеры АТУ.
