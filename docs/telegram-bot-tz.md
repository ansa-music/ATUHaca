# ТЗ: Telegram-бот Qadir

Задание для отдельной сессии разработки. Бот — дополнительный канал ввода и напоминаний к уже работающей системе Qadir. Основная система не меняется.

## Жёсткие рамки

- Работать **только в папке `bot/`** этого репозитория (`ansa-music/ATUHaca`). Файлы в `src/`, `supabase/`, `docs/`, корневые `package.json`, `README.md` не трогать — их ведёт другая сессия.
- Схему базы не менять и SQL в Supabase не выполнять. Бот пользуется тем, что уже есть.
- Не использовать сервисный ключ Supabase (`service_role`). Бот работает от имени пользователя, который в нём вошёл, — тогда права проверяет сервер (RLS), как и в веб-версии.
- Токен бота и любые пароли — только в `bot/.env`, который не попадает в git. Добавить `bot/.env.example` без значений.
- Срок: рабочий бот за 60–90 минут. Сначала сценарий из раздела «Минимум», остальное — если останется время.

## Стек

Node.js 18+, [grammY](https://grammy.dev), `@supabase/supabase-js`. Режим long polling (без вебхуков и хостинга): бот запускается на ноутбуке командой `npm start` из папки `bot/`. Свой `bot/package.json`.

## Подключение к Supabase

```
SUPABASE_URL=https://carnvxpthrxpqklbpnja.supabase.co
SUPABASE_ANON_KEY=<публичный anon-ключ — взять из файла .env.local в корне проекта, переменная VITE_SUPABASE_ANON_KEY>
BOT_TOKEN=<токен от @BotFather>
```

Anon-ключ публичный: доступ ограничивают политики RLS. На каждого вошедшего пользователя Telegram бот держит **отдельный клиент** Supabase:

```js
const client = createClient(SUPABASE_URL, SUPABASE_ANON_KEY, { auth: { persistSession: false, autoRefreshToken: true } })
await client.auth.signInWithPassword({ email, password })
```

Хранить в памяти `Map<chatId, { client, profile, org }>`. При перезапуске бота пользователь входит заново — для демо этого достаточно.

## Вход

- `/start` — приветствие и подсказка: «Отправьте e-mail и пароль через пробел».
- Пользователь присылает `e-mail пароль` → бот входит, **сразу удаляет сообщение с паролем** (`ctx.deleteMessage()`), читает профиль и организацию:
  - `profiles`: `select * … eq('id', user.id)` → поля `full_name`, `role`, `org_id`;
  - `organizations`: `select * … eq('id', org_id)` → `name_ru`, `name_kk`.
- Бот предназначен для роли `responsible` (ответственное лицо). Остальным ролям показывает только команду `/status` (сводка по отчётам) и вежливо сообщает, что ввод доступен ответственным лицам.
- `/logout` — выход и удаление клиента из памяти.

Демо-логины и пароль — в корневом `README.md`, раздел «Демо-логины».

## Данные, с которыми работает бот

| Объект | Как использовать |
|---|---|
| `get_or_create_report(p_month date)` — RPC | Возвращает отчёт организации за месяц (создаёт черновик, если его нет). Вызывать с первым числом текущего месяца: `client.rpc('get_or_create_report', { p_month: '2026-11-01' })`. В ответе `id`, `status`, `period_start`, `period_end`. |
| `waste_types` | Виды отходов: `select * … or('org_id.eq.<org>,org_id.is.null') .eq('is_active', true)`. Поля: `id`, `name_ru`, `name_kk`, `unit` (`kg` / `l`), `default_disposal_id`, `category`. |
| `disposal_methods` | Способы утилизации: `id`, `name_ru`, `name_kk`. |
| `entries` — вставка | `{ report_id, org_id, entry_date: 'YYYY-MM-DD', waste_type_id, quantity, disposal_id, source: 'manual' }`. Поле `user_id` подставляет сервер. |
| `entries` — чтение | `select * … eq('report_id', id)` — для итогов за день и месяц. |
| `submit_report(p_report uuid)` — RPC | Отправляет отчёт на проверку. |
| `reports` | Статус отчёта: `draft`, `submitted`, `in_review`, `accepted`, `returned`. |
| `status_history` | Комментарий проверяющего: последняя строка с `to_status = 'returned'`, поле `comment`. |

Ограничения сервера, которые бот должен показывать человеку понятным текстом, а не падать:

- количество: больше 0 и не больше 500;
- дата не в будущем и внутри месяца отчёта;
- вставка и правка возможны только при статусе отчёта `draft` или `returned`; иначе сервер ответит отказом (ноль затронутых строк или ошибка политики) — бот пишет: «Отчёт уже отправлен на проверку, записи менять нельзя».

Дата «сегодня» — по времени Алматы (UTC+5), а не UTC.

## Минимум (обязательно)

**Быстрый ввод взвешивания — не больше трёх действий:**

1. `/add` или кнопка «➕ Внести» → бот показывает виды отходов организации inline-кнопками (по 2 в ряд).
2. Нажатие на вид → бот просит: «Сколько? Отправьте число, например 4,7» и показывает единицу (кг или л).
3. Пользователь присылает число (принимать и запятую, и точку) → бот сохраняет запись со способом утилизации по умолчанию и отвечает:
   «✅ Пищевые отходы из зала — 4,7 кг. Сегодня: 12,3 кг. За месяц: 530,9 кг».

Короткий путь: сообщение вида `хлеб 3,2` или `масло 1.5` — бот ищет вид отхода по вхождению слова в название и сохраняет сразу; если подходит несколько — показывает кнопки с вариантами.

**Команды:**

- `/today` — записи и итог за сегодня по видам.
- `/month` — итоги за месяц по видам, отдельно кг и л.
- `/status` — статус отчёта за текущий месяц; если `returned` — комментарий проверяющего.
- `/submit` — подтверждение кнопками «Отправить / Отмена», затем `submit_report`.
- `/help`.

После входа показывать постоянную клавиатуру: «➕ Внести», «📅 Сегодня», «📊 Месяц», «📋 Статус».

## Желательно

- **Уведомление о решении проверяющего.** Раз в 30 секунд бот проверяет статус отчёта каждого вошедшего пользователя; при смене на `returned` пишет «↩️ Отчёт возвращён: «комментарий»», при `accepted` — «✅ Отчёт за ноябрь принят».
- **Напоминание о сроке.** `/remind` у пользователя с ролью `reviewer`: бот читает `reports` за прошлый месяц и пишет всем вошедшим ответственным, у чьей организации нет отчёта со статусом `accepted`: «⏰ Напоминание: отчёт за октябрь не сдан».
- **Фото.** Если прислано фото с подписью-числом — сохранить запись после выбора вида отхода. Само фото в базу не загружать.
- **Языки.** `/lang` — русский и казахский; названия брать из `name_ru` / `name_kk`.

## Не делать

- Регистрацию пользователей, админские функции, проверку отчётов в боте.
- Хранение паролей: пароль используется один раз для входа и нигде не сохраняется и не логируется.
- Вебхуки, базу данных бота, Docker.

## Что сдать

- `bot/index.js` (или несколько файлов), `bot/package.json`, `bot/.env.example`, `bot/README.md` с запуском в три команды и списком команд бота.
- Проверка перед сдачей: войти под `iskander@qadir.kz`, внести запись, увидеть её в веб-версии на странице «Ввод» той же организации; `/status` показывает текущий статус; попытка внести запись в отправленный отчёт даёт понятное сообщение.
- Один коммит только с папкой `bot/`. Перед пушем сделать `git pull --rebase`, чтобы не затереть чужие изменения.
